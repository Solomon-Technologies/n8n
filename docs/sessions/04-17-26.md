# 2026-04-17 — Production DB recovery + upstream sync

## Part A — Fixed www.n8n.solomon.technology crash loop

### Symptom
Railway container crashed on boot:
```
Initializing n8n process
There was an error initializing DB
connect ENETUNREACH 2600:1f16:1cd0:3334:dfd7:a640:9d55:be73:5432 - Local (:::0)
```

### Root cause
`DB_POSTGRESDB_HOST=db.ftoakolakzpytcsflrsv.supabase.co` is Supabase's **direct** endpoint. New Supabase projects expose the direct endpoint on **IPv6 only** — no A record. Railway's default egress doesn't route to Supabase's IPv6. `NODE_OPTIONS=--dns-result-order=ipv4first` was a no-op because there was no IPv4 to prefer.

### Fix (Railway → n8n service → Variables)
Switched to Supabase's Shared Supavisor **Session pooler**, which is IPv4-proxied for free:

| Variable | From | To |
|---|---|---|
| `DB_POSTGRESDB_HOST` | `db.ftoakolakzpytcsflrsv.supabase.co` | `aws-1-us-east-2.pooler.supabase.com` |
| `DB_POSTGRESDB_USER` | `postgres` | `postgres.ftoakolakzpytcsflrsv` |
| `NODE_OPTIONS` | `--dns-result-order=ipv4first` | *(removed)* |

Port stayed `5432` (session mode). Password, schema (`n8n`), `SSL_REJECT_UNAUTHORIZED=false` unchanged.

### Why session mode (port 5432) not transaction (6543)
n8n keeps long-lived connections, runs migrations on boot, and uses prepared statements. Transaction mode returns connections to the pool after each transaction and breaks prepared statements — would have caused a different crash on startup.

### Supavisor gotcha
The user suffix (`postgres.<project_ref>`) is **required** — Supavisor demultiplexes tenants by username. Plain `postgres` returns `Tenant or user not found`.

### Where to find pooler strings in 2026 Supabase UI
The "Connection Pooling" settings page only tunes pool size and shows logs. Connection strings moved behind the **Connect** button at the top of the dashboard:
`https://supabase.com/dashboard/project/<project-ref>?showConnect=true&method=session`

### Verification
- Deploy logs show `Initializing n8n process` → editor accessible, no `ENETUNREACH`
- Site loads, login renders
- No code changes in this repo — all on Railway dashboard
